# quality-gates

The engineering standards that projects built with AI coding agents, by people
who are not software engineers, pin and are held to.

## People and projects

**Builder**:
The person who directs coding agents and judges whether the result works, but
does not review the code.
_Avoid_: user, developer, operator

**Consumer**:
A project that pins a tag of this repo and is held to its standards.
_Avoid_: client, downstream project

**Pin**:
The release tag a consumer installs; a fix reaches a consumer only when its pin
is bumped.
_Avoid_: version, dependency

**Upstream**:
A published body of work this repo copies and adapts text from, such as Matt
Pocock's skills or Lauren Tan's pstack; watched for changes and re-copied here.
_Avoid_: vendor, source

**Dependency**:
An outside tool a component runs but this repo does not copy, such as radon or
lizard; updated by bumping its version.
_Avoid_: upstream, vendor

## Components

**Component**:
One capability a consumer switches on or off as a whole, with all its parts:
for example a gate's command, skill, baseline and CI step together.
_Avoid_: module, plugin, feature, part

**Choice file**:
The committed `quality-gates.json` that records which components a consumer
chose or declined, its languages and its commit time limit (ADR-007).
_Avoid_: config, settings, lock file

**Explainer**:
A component's plain-words page, shipped with each release: what it catches, why
it matters, what it asks of the builder, and where to read more.
_Avoid_: help text, docs page

**Core**:
The components every consumer has and cannot switch off: the workflow, the
principles and the asking rule.
_Avoid_: base, defaults

## The three layers

**Workflow**:
The order of work, chosen by the size of the work.

**Size rule**:
The table that maps the size of the work to the skill it starts at.
_Avoid_: routing, triage

**Principle**:
A named, one-rule standard for judging a step, applied by the agent reading it.
_Avoid_: rule, guideline, value

**Lesson**:
A correction recorded in one project; it becomes a principle or a gate only
when it has recurred and would recur elsewhere.
_Avoid_: learning, retro item

**Gate**:
A command that fails the commit or the build when a standard is broken, needing
no one's cooperation.
_Avoid_: linter, check, rule

**Function**:
What a complexity gate scores: a function, a method, a closure, or a method of
a nested class, each scored on its own. A class is never scored. In Swift a
closure is the exception: lizard counts its branches in the function that holds
it, and its untested lines do not lower that function's coverage (#53). A Swift
closure that no function holds (file scope, a stored property, a `lazy var`) is
not scored at all.
_Avoid_: block, unit

**Unmeasured**:
A Function the coverage report holds no usable figure for, because the report
never saw its file or cannot place it within one. It is a gap in measuring, not
untested code, and it fails the CRAP gate until it is measured.
_Avoid_: unknown coverage, 0% covered, untested

**Asking rule**:
When and how an agent puts a decision to the builder: plain stakes, two or
three options, a recommendation.

**Reference file**:
A rule copied from an ADR into each skill that cites it, as
`references/<rule>.md`; generated by `qg-references` from a tagged ADR section,
never edited by hand.
_Avoid_: rule copy, snippet

**Restated rule**:
A dated section at the end of an ADR that states one rule's current text in
full, so it can be tagged and shipped as a reference file without editing the
accepted text it restates.
_Avoid_: rule summary, consolidated rule

**Stage guard**:
The gate that refuses an agent's bulk staging of changed files.
_Avoid_: git guardrail, commit guard

## Understanding

**Project map**:
The one document per project that shows the builder its outcome, its shape,
the route through the stages, the choices settled and open, and loose ends.
Each job adds to it in proportion to its size.
_Avoid_: roadmap, plan, overview

**Checkpoint**:
The plain-words note the builder gets at a stage boundary: what was decided,
what it cost and what is next. Its lasting effect is the update it makes to the
project map.
_Avoid_: status report, summary, gate report

**Stage boundary**:
One of the five points where a checkpoint is given: idea settled, spec agreed,
built, proven, released.
_Avoid_: milestone, phase gate

## Debt

**Debt**:
Violations of a gate that existed when the gate was adopted.

**Baseline**:
The committed record of a gate's debt; the gate fails only on what is new or
worse, and on paid debt not yet recorded.
_Avoid_: allowlist, ignore file, suppression

**Recorded reason**:
A project's written decision to relax a gate for one case: why, what would let
the case come back, and, where the gate asks, a review date or a trigger. Unlike
debt, it is a choice (ADR-006).
_Avoid_: waiver, ignore entry, exemption

**Loosening**:
A recorded reason that relaxes a standard for the whole project rather than one
case: switching off a gate the project has, raising a limit, or removing a
language that still has code. It needs the builder's explicit yes and always
shows as a warning.
_Avoid_: override, opt-out, exemption

**Catch**:
A problem a gate stopped, counted once and ended as fixed, given a reason, or
accepted as debt. Not a proven bug.
_Avoid_: bug caught, issue caught
